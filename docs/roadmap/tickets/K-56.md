**Phạm vi:**

- Package `internal/mailer` (thuần, không `net/http`): `Message`, `Mailer` interface,
  `LogMailer`, template `VerifyEmail(locale, link)` song ngữ.
- Package `internal/mailer/resend`: `Client` gọi `POST https://api.resend.com/emails`.
- Service:
  - `Register` nhận `RegisterInput{Email, Password, Locale}`; đăng ký xong gửi mail xác minh.
    Gửi lỗi thì **vẫn đăng ký thành công**, chỉ ghi log; người dùng gửi lại từ banner.
  - `RequestVerification(userID, locale)`, `VerifyEmail(rawToken)`, `Me(userID)`.
  - Token thô 32 byte (dùng lại `auth.NewRefreshToken`), DB chỉ giữ SHA-256. TTL 24 giờ.
  - Ân hạn 7 ngày tính từ `created_at`. Hết hạn mà chưa xác minh thì mọi route dữ liệu trả
    403 code `1460`; route `/auth/*` vẫn chạy.
- HTTP:
  - `POST /api/auth/verify` công khai, body `{token}`, giới hạn 20 lần / 10 phút / IP.
  - `GET /api/auth/me` (đăng nhập) → `{id, email, locale, email_verified, verify_deadline,
    verification_required}`.
  - `POST /api/auth/verify/request` (đăng nhập) body `{locale}`, giới hạn 3 lần / giờ / IP.
  - Middleware `RequireVerifiedEmail` gắn vào nhóm route dữ liệu và route Replay.
- Config: `RESEND_API_KEY`, `MAIL_FROM`, `APP_URL`.
- FE:
  - Trang công khai `/verify-email?token=…`.
  - Banner trong `AppShell` khi chưa xác minh, có nút "Gửi lại email".
  - Hết ân hạn: thay nội dung trang bằng màn hình yêu cầu xác minh.
  - Đăng ký gửi kèm `locale` hiện tại.
  - Code `1460` có câu dịch riêng.

- Mã mời (R-2, K-57). Luật "chỉ user đầu tiên" giữ nguyên ở ticket này.

**Edge case:**

- Token dùng hai lần (người dùng bấm link hai lần, hoặc StrictMode gọi effect hai lần) → lần hai
  400; FE chặn gọi lần hai.
- Token hết hạn → 400, cùng câu với token sai (không phân biệt để khỏi lộ thông tin).
- Mở link ở trình duyệt khác chưa đăng nhập → vẫn xác minh được (route công khai).
- Resend trả 4xx/5xx hoặc timeout → đăng ký vẫn xong; gửi lại trả 502.
- User đổi ngôn ngữ giao diện sau khi đăng ký → thư gửi lại dùng ngôn ngữ đang hiển thị.
- Ngày thứ 8 chưa xác minh → refresh, logout, me, verify/request vẫn chạy, chỉ route dữ liệu bị chặn.
- User có từ trước migration → coi là đã xác minh, không thấy banner.
