đọc số lỗ mỗi ngày trên bảng lệnh và dashboard. `bridge.css` đã có sẵn `--loss-text`
(red/700 sáng, red/300 tối) và `--warn-text` đạt chuẩn nhưng chưa được dùng ngoài landing.

**Phạm vi:**
- Mọi class **chữ** `text-destructive` → `text-loss`, `text-warning` → `text-warn` trong `frontend/src`
  (kể cả `hover:` và biến thể `/90` của shadcn `alert`).
- Cổng chặn trong `src/test/styleguard.test.ts` để không ai dùng lại class cũ cho chữ.
- Cập nhật test đang assert theo tên class.

**Ngoài phạm vi:**
- Mảng màu: `bg-destructive`, `border-destructive`, thanh đo, vùng gạch — giữ `--status-error`.
- `text-destructive-foreground` (chữ trên nền lỗi) — token khác, giữ.
- `text-success`, `text-info` (báo cáo ghi `--status-info` 3,68:1) — thẻ riêng nếu cần.
- Màu biểu đồ (`--chart-loss`).

**Tiêu chí nghiệm thu:**
- [ ] Không còn `text-destructive` / `text-warning` (không kèm hậu tố `-…`) trong code nguồn FE ngoài test.
- [ ] Styleguard fail khi thêm lại class cũ, pass trên code mới.
- [ ] CSS build sinh ra `.text-loss`, `.text-warn`, `hover:text-loss`, `text-loss/90`.
- [ ] `--loss-text` / `--warn-text` đạt ≥ 4,5:1 trên các nền surface chính, cả sáng lẫn tối.
- [ ] Ngưỡng màu KPI (profit factor, recovery factor) giữ đúng bậc §8.2, chỉ đổi token chữ.
- [ ] `tsc`, Vitest, build xanh.

**Edge case:** số 0 vẫn trung tính; chữ lỗi form trong dialog (nền `--surface-modal`); dark mode.
