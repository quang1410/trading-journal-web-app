## 1. BA check

**Bối cảnh:** `AuthService.Refresh` đọc token, kiểm `RevokedAt == nil`, rồi mới thu hồi.
Hai request song song cùng một refresh token đều qua bước kiểm và **cả hai nhận phiên mới**.
Kẻ trộm token chạy đua với người dùng thật có phiên riêng mà cơ chế phát hiện tái sử dụng
không bắt được.

**Phạm vi:**
- `RefreshTokenStore.Rotate`: thu hồi token cũ (`WHERE revoked_at IS NULL`) và lưu token mới
  trong **một transaction**; trả `false`, không lưu gì, khi token cũ đã chết.
- `Refresh` dùng `Rotate`; `false` → xử như tái sử dụng: `RevokeAllForUser` + 401
  `msgInvalidSession`.
- `Revoke` và `Logout` giữ nguyên như `main`.
- Memstore của test khớp hành vi repo thật.

**Ngoài phạm vi:** rate limit (K-04); dọn bảng `refresh_tokens`; đổi TTL; nhiều tab refresh
cùng lúc (K-30).

**Tiêu chí nghiệm thu:**
- [ ] Hai refresh cùng token, cả hai đọc thấy token còn sống → bên thua 401, không phát phiên.
- [ ] Khi đó mọi phiên còn sống của user bị thu hồi, **kể cả phiên của bên thắng — ở mọi thứ tự xen kẽ giữa các request dùng cùng token đó**. (Thứ tự xoay tiếp token thế hệ sau trong lúc đang thu hồi: ngoài phạm vi, thẻ K-33.)
- [ ] Regression test fail trên code cũ, pass trên code mới.
- [ ] Contract test cho `Rotate` (thành công / token đã chết / id lạ) chạy trên cả memstore và Postgres.
- [ ] Trên Postgres thật, nhiều goroutine refresh cùng token: tối đa một phiên, không token nào sống sót sau khi phát hiện tái sử dụng.
- [ ] Mốc thu hồi đầu tiên không bị ghi đè.
- [ ] Luồng refresh bình thường, logout, token hết hạn, token lạ không đổi hành vi.
- [ ] `go vet` sạch, `make test` xanh, `-race` xanh.

**Edge case:** lỗi DB khi Rotate → 500 (không phải 401); id không tồn tại → false.

**Quy tắc CLAUDE.md bị chạm:** 9 (code/test tiếng Anh, comment tiếng Việt, `msg` lỗi nghiệp
vụ tiếng Việt).
